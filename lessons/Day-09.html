  • Understand stable Pod identity, ordered deployment, headless Services and per-replica storage.
Study the concepts first, then perform the lab in a disposable training environment. Understand every command before running it.

2. Concepts and Technical Explanations

StatefulSet

Manages Pods that require stable identity and often persistent storage.

Stable identity

Pod names and network identity follow an ordinal pattern.

Headless Service

A Service with clusterIP None that supports direct endpoint discovery.

volumeClaimTemplates

Creates a PVC for each StatefulSet replica.

Ordered lifecycle

StatefulSet supports ordered creation and termination behavior.

5. YAML Example

apiVersion: v1
kind: Service
metadata:
  name: database
spec:
  clusterIP: None
  selector:
    app: database
  ports:
  - port: 5432
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: database
spec:
  serviceName: database
  replicas: 2
  selector:
    matchLabels:
      app: database
  template:
    metadata:
      labels:
        app: database
    spec:
      containers:
      - name: database
        image: postgres:16
        ports:
        - containerPort: 5432
        env:
        - name: POSTGRES_PASSWORD
          value: lab-only-password
        volumeMounts:
        - name: data
          mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: [ReadWriteOnce]
      resources:
        requests:
          storage: 2Gi

Review the API version, kind, metadata, selectors, labels, Pod template and container configuration. Save the example as a YAML file before applying it. Adapt placeholders to your environment.

8. Troubleshooting Scenarios

PVC Pending: inspect StorageClass. Pod startup failure: inspect image, environment and storage permissions. StatefulSet alone does not provide database replication or backup.

Structured troubleshooting method

  1. Identify the scope and customer impact.
  2. Capture Pod status, node status and events.
  3. Inspect resource descriptions and logs.
  4. Compare the current state with the desired configuration.
  5. Check recent changes and dependencies.
  6. Apply a controlled correction.
  7. Verify recovery and document the root cause.

9. Production Considerations

  • Use least privilege and protect credentials.
  • Use resource requests and limits where appropriate.
  • Validate changes in a non-production environment.
  • Monitor application health and infrastructure health.
  • Maintain backups for important stateful data.
  • Document ownership, recovery and rollback procedures.
