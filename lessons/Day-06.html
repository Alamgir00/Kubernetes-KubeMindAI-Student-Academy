2. Concepts and Technical Explanations

Label

A key-value pair attached to an object for identification and selection.

Selector

A query that identifies objects based on labels.

Namespace

A logical scope for namespaced resources.

Annotation

Metadata for additional information not normally used for selection.

Label convention

Consistent keys make automation and operations easier.

4. Important Commands

kubectl get namespaces
kubectl create namespace dev
kubectl get pods --show-labels
kubectl get pods -l app=web
kubectl label pod POD_NAME environment=dev
kubectl get all -n dev

Run commands in the correct cluster context and namespace. Replace example names with the actual names returned by your cluster.

5. YAML Example

apiVersion: v1
kind: Namespace
metadata:
  name: dev
---
apiVersion: v1
kind: Pod
metadata:
  name: web
  namespace: dev
  labels:
    app: web
    environment: dev
  annotations:
    owner: platform-team
spec:
  containers:
  - name: nginx
    image: nginx:1.27

Review the API version, kind, metadata, selectors, labels, Pod template and container configuration. Save the example as a YAML file before applying it. Adapt placeholders to your environment.

6. Hands-on Practical Lab

Create dev and test namespaces; deploy Pods into each; label them; select only the dev Pods; inspect how namespace-scoped commands behave.

Suggested lab sequence

  1. Verify your current Kubernetes context.
  2. Inspect existing resources before changing anything.
  3. Create the lab resources using the supplied YAML.
  4. Watch the resource status and Kubernetes events.
  5. Test the expected behavior.
  6. Record the output and explain what happened.
  7. Clean up only resources created for this exercise.

7. Verification and Expected Results

kubectl get pods -n dev --show-labels; kubectl get pods -l environment=dev -n dev.

Success means the expected resource state and behavior are visible. A command returning successfully is not sufficient if the workload is not healthy.

8. Troubleshooting Scenarios

Resource not found: verify namespace and context. Selector returns nothing: inspect exact label keys and values. Cluster-scoped resources do not belong to namespaces.

Structured troubleshooting method

  1. Identify the scope and customer impact.
  2. Capture Pod status, node status and events.
  3. Inspect resource descriptions and logs.
  4. Compare the current state with the desired configuration.
  5. Check recent changes and dependencies.
  6. Apply a controlled correction.
  7. Verify recovery and document the root cause.

9. Production Considerations

  • Use least privilege and protect credentials.
  • Use resource requests and limits where appropriate.
  • Validate changes in a non-production environment.
  • Monitor application health and infrastructure health.
  • Maintain backups for important stateful data.
  • Document ownership, recovery and rollback procedures.
